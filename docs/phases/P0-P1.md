# Phase 0 & Phase 1 Execution Plan

This document defines the task-by-task breakdown, file lists, exact commands, and verification checkpoints for **Phase 0 (Foundation v0.0)** and **Phase 1 (Core Playback Beta v0.1)** of Statistical Player.

---

## Phase 0: Foundation (v0.0)

### Goal
Establish the repository structure, toolchain configuration, cross-platform CI, logging, panic safety, settings persistence, and a basic native window with custom Poppins typography and Dark/Light theme switching.

### Task 0.1: Project Skeleton & Toolchain Configuration
- **Files**:
  - `Cargo.toml`: Package definition with edition 2024 and optimized dependency dev/release profiles (Section 5).
  - `.gitignore`, `.gitattributes`: Ignore build artifacts, local settings, caches, and database files; force auto line endings and binary font handling.
  - `CLAUDE.md`, `AGENTS.md`: AI instructions, hard rules, and verification workflow.
  - `.github/workflows/ci.yml`: Multi-platform matrix CI check on Windows, macOS, and Linux.
- **Commands**:
  - `cargo fmt --all -- --check`
  - `cargo clippy --all-targets -- -D warnings`
  - `cargo test --all`
- **Checkpoint**: Cargo builds cleanly with zero warnings.

### Task 0.2: Core Modules & Settings Persistence
- **Files**:
  - `src/core/settings.rs`: Typed `Settings` struct (window size, theme mode, last opened folder, visualizer fps, background play preference). Uses `directories::ProjectDirs` to store `settings.toml` in the platform config directory.
  - `src/core/mod.rs`: Module exports and basic command/snapshot types.
- **Commands**:
  - `cargo test core::settings`
- **Checkpoint**: Settings can be serialized, loaded, updated, and saved reliably with graceful defaults if the file is absent.

### Task 0.3: Logging & Panic Hook
- **Files**:
  - `src/logging.rs`: Initialize `tracing` subscriber with non-blocking appender writing to `<data_dir>/logs/player.log` and stderr with ANSI formatting.
  - Custom panic hook in `src/main.rs`: Logs thread panic messages and backtraces to disk safely.
- **Checkpoint**: Startup logs appear in the console and log directory.

### Task 0.4: Eframe Window, Poppins Fonts & Theming
- **Files**:
  - `assets/fonts/`: Bundled `Poppins-Regular.ttf`, `Poppins-Medium.ttf`, `Poppins-SemiBold.ttf` and `OFL.txt`.
  - `src/ui/theme.rs`: Color token palettes for Dark and Light modes (Section 10).
  - `src/ui/fonts.rs`: Registers Poppins font definitions into egui's font context.
  - `src/ui/app.rs`: Initial `eframe::App` implementation displaying theme toggle button, current settings status, and window frame.
  - `src/main.rs`: Entry point initializing logging, settings, fonts, and launching eframe with the wgpu backend.
- **Checkpoint**:
  - `cargo run` opens a clean 960x640 window on Windows.
  - Toggling between Light and Dark themes immediately updates background, panels, and text colors.
  - Text renders crisply in Poppins typography.

## Phase 1: Core Playback Beta (v0.1)

### Goal
Provide a reliable, responsive folder-based player that decodes FLAC (16/24-bit), MP3, and AAC (M4A) via Symphonia and CPAL through an atomic lock-free ring buffer, with background tag scanning, virtualized queue list, transport controls, and an audit tool.

### Task 1.1: Audio Engine & Null Sink
- **Dependencies**: `symphonia` (with `mp3`, `aac`, `flac`, `wav`, `pcm`), `cpal`, `rtrb`.
- **Files**:
  - `src/audio/engine.rs`: Audio decoder pipeline feeding an `rtrb` bounded lock-free ring buffer (~200ms).
  - `src/audio/sink.rs`: Audio sink trait with `CpalSink` for real output and `NullSink` for automated tests and CI without a sound card.
  - `src/audio/source.rs`: Format prober and interleaved `f32` conversion with channel downmix.
  - `tests/audio_pipeline_tests.rs`: Verification of sample frame accuracy, volume curve, and seeking on generated sine tone fixtures.
- **Hard Rules**: Zero allocations, locks, logging, or panics in the audio callback.
- **Checkpoint**: Unit tests pass against `NullSink` decoding fixture files.

### Task 1.2: Player Core Thread & State Machine
- **Dependencies**: `crossbeam-channel`.
- **Files**:
  - `src/core/player.rs`: Dedicated player core thread owning the queue, state machine (Stopped, Loading, Playing, Paused), position timing interpolation, and atomic counter updates.
  - `src/core/commands.rs`: Commands (`Play`, `Pause`, `Resume`, `Toggle`, `Stop`, `Next`, `Previous`, `Restart`, `Seek`, `SetVolume`, `ReplaceQueue`, `Randomize`, `SetRepeat`, `Quit`).
  - `src/core/snapshot.rs`: Immutable `PlayerSnapshot` published to the UI thread.
- **Checkpoint**: Queue advance, repeat modes (Off, Track, Queue), one-shot randomize, and seamless state transitions verified via tests.

### Task 1.3: Background Tag Reader & Folder Loader
- **Dependencies**: `lofty`, `walkdir`, `crossbeam-channel`.
- **Files**:
  - `src/library/loader.rs`: Background scanner reading folder audio files and extracting metadata (title, artist, album, duration, codec, bitrate, sample rate, bit depth) without blocking the UI.
  - Progressive updates: sends batches of scanned tracks to the UI so large folders (like the 2,670 compilation) show immediate rows within 2 seconds.
- **Checkpoint**: Loading large directories does not freeze UI interaction.

### Task 1.4: Minimal Playback UI
- **Dependencies**: `egui_extras` (virtualized table).
- **Files**:
  - `src/ui/queue_table.rs`: Virtualized table displaying columns: Playing marker, track number, title, artist, year, length.
  - `src/ui/control_bar.rs`: Transport buttons (Restart, Prev, Stop, Play/Pause, Next, Randomize, Repeat), elapsed/total time, volume slider with mute toggle, and format line.
  - `src/ui/debug_overlay.rs`: F12 debug overlay showing frame time, repaints/sec, buffer fill, and underruns.
- **Checkpoint**: Full UI allows selecting music folders via dialog or drag-and-drop, playing tracks, seeking, and adjusting volume.

### Task 1.5: Library Audit CLI Tool
- **Files**:
  - `src/library/audit.rs`: Subcommand `cargo run -- audit <folder>`. Walks a folder, decodes 1 second of every audio file, and generates a structured summary in `docs/AUDIT_REPORT.md`.
- **Checkpoint**: Tool successfully audits test library folders and reports codec distributions and anomalies.
